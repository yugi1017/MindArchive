# AI名词解释

> 掌握AI领域的核心术语，建立专业认知框架

## 一、基础概念

### AI（Artificial Intelligence）人工智能

**专业解释**：
人工智能是计算机科学的一个分支，致力于创建能够执行通常需要人类智能的任务的系统，包括学习、推理、问题解决、感知和语言理解。

**形象比喻**：
AI就像一个"数字大脑"，能够模仿人类的思考方式来完成任务。就像教小孩一样，我们给它"看书"（数据），它学会"思考"（算法），最终能"做事"（应用）。

**应用场景**：
- 智能助手（Siri、小爱同学）
- 自动驾驶
- 医疗诊断
- 推荐系统

---

### LLM（Large Language Model）大语言模型

**专业解释**：
大语言模型是一种基于Transformer架构的深度学习模型，通过在海量文本数据上进行预训练，学习语言的统计规律和知识表示，能够理解和生成自然语言。

**形象比喻**：
LLM就像一个"读过全世界图书馆的书"的超级学霸。它不是死记硬背，而是学会了语言的"语法规则"和"知识关联"，所以能举一反三。

**核心特点**：
- 参数规模大（数十亿到数千亿）
- 预训练+微调的训练范式
- 涌现能力（规模大到一定程度后出现新能力）

**代表模型**：
- GPT系列（OpenAI）
- Claude系列（Anthropic）
- Gemini系列（Google）
- DeepSeek系列

---

### NLP（Natural Language Processing）自然语言处理

**专业解释**：
自然语言处理是AI和语言学的交叉领域，专注于让计算机理解、解释和生成人类语言。

**形象比喻**：
NLP是AI的"语言老师"，教计算机如何"听懂"和"说话"人类语言。就像翻译官一样，在人类语言和计算机语言之间架起桥梁。

**主要任务**：
- 文本分类
- 情感分析
- 机器翻译
- 问答系统
- 文本摘要

---

## 二、核心技术概念

### Token（标记/词元）

**专业解释**：
Token是模型处理文本的最小单位，可以是词、子词或字符。文本在被输入模型前会被分割成一系列token。

**形象比喻**：
Token就像是语言的"乐高积木"。模型不是一次处理整篇文章，而是把它拆成一块块"积木"（token），然后逐个处理。

**实际例子**：
```
原文："Hello, world!"
Token化：["Hello", ",", " world", "!"]  (4个tokens)
```

**为什么重要**：
- 影响API费用（按token计费）
- 决定上下文长度限制
- 不同模型的token化方式不同

---

### Context Window（上下文窗口）

**专业解释**：
上下文窗口是模型一次能处理的最大token数量，包括输入和输出。它决定了模型能"记住"多少信息。

**形象比喻**：
上下文窗口就像模型的"工作记忆容量"。想象你在做数学题，草稿纸大小有限，只能写下一定数量的内容。上下文窗口就是这张"草稿纸"的大小。

**各模型对比**：

| 模型 | 上下文窗口 | 约等于汉字数 |
|------|------------|--------------|
| GPT-4o | 128K | ~10万字 |
| Claude 4.5 | 1M | ~75万字 |
| Gemini 2.5 | 1M | ~75万字 |
| DeepSeek | 128K | ~10万字 |

---

### Prompt（提示词）

**专业解释**：
Prompt是用户输入给模型的指令和上下文信息，用于引导模型生成期望的输出。

**形象比喻**：
Prompt就像给AI的"任务说明书"。你写得越清楚，AI完成得越好。就像给新员工布置任务，说明越详细，结果越符合预期。

**Prompt结构**：
```
┌─────────────────────────────────────┐
│  角色设定：你是一个...               │
│  任务描述：请帮我...                 │
│  输出格式：按照以下格式...           │
│  示例参考：例如...                   │
│  约束条件：注意...                   │
└─────────────────────────────────────┘
```

---

### Temperature（温度参数）

**专业解释**：
Temperature是控制模型输出随机性的超参数，取值范围通常为0-2。值越低输出越确定，值越高输出越随机。

**形象比喻**：
Temperature就像"创意调节旋钮"：
- 低温度（0-0.3）：像严谨的工程师，回答稳定、可预测
- 高温度（0.7-1.0）：像创意作家，回答多样、有惊喜

**使用建议**：

| 场景 | 推荐温度 |
|------|----------|
| 代码生成 | 0-0.3 |
| 事实问答 | 0-0.2 |
| 创意写作 | 0.7-1.0 |
| 头脑风暴 | 0.8-1.2 |

---

## 三、高级概念

### Agent（智能体）

**专业解释**：
Agent是一种能够感知环境、自主决策并采取行动以实现目标的AI系统。它不仅能对话，还能调用工具、执行任务、与环境交互。

**形象比喻**：
传统AI像"顾问"，只能给建议；Agent像"员工"，能真正"干活"。它有"大脑"（LLM）、"手脚"（工具调用）、"记忆"（上下文），能独立完成复杂任务。

**Agent核心能力**：
```
┌─────────────────────────────────────┐
│              Agent架构              │
├─────────────────────────────────────┤
│  感知 → 理解用户需求和环境          │
│  规划 → 分解任务、制定计划          │
│  执行 → 调用工具、执行操作          │
│  反思 → 评估结果、调整策略          │
└─────────────────────────────────────┘
```

**与普通AI的区别**：

| 特性 | 普通AI | Agent |
|------|--------|-------|
| 交互方式 | 单轮问答 | 多轮任务执行 |
| 能力范围 | 仅对话 | 可调用工具 |
| 自主性 | 被动响应 | 主动规划执行 |
| 记忆 | 有限上下文 | 长期记忆 |

---

### MCP（Model Context Protocol）模型上下文协议

**专业解释**：
MCP是由Anthropic提出的开放协议，用于标准化AI模型与外部数据源、工具之间的连接方式，实现"即插即用"的集成。

**形象比喻**：
MCP就像AI领域的"USB接口"。以前，每个外设（鼠标、键盘、打印机）都需要不同的接口；有了USB，所有设备都能用同一个接口连接。MCP让AI能统一连接各种工具和数据源。

**MCP架构**：
```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│    Host      │────▶│    Client    │────▶│    Server    │
│  (AI应用)    │     │   (桥梁)     │     │ (数据/工具)  │
└──────────────┘     └──────────────┘     └──────────────┘
    Claude              MCP Client          文件系统
    Desktop                                  数据库
                                             API服务
```

**为什么重要**：
- 统一标准，减少重复开发
- 即插即用，快速扩展能力
- 安全可控，权限管理清晰

---

### RAG（Retrieval-Augmented Generation）检索增强生成

**专业解释**：
RAG是一种结合信息检索和文本生成的技术，通过从外部知识库检索相关信息，增强模型的回答质量和准确性。

**形象比喻**：
RAG就像给AI配了一个"随身资料库"。普通AI是"闭卷考试"，只能靠记忆；RAG是"开卷考试"，可以随时查阅资料再回答。

**RAG工作流程**：
```
用户提问
    ↓
┌─────────────────┐
│  1. 问题理解    │
└────────┬────────┘
         ↓
┌─────────────────┐
│  2. 检索知识库  │ ← 外部知识库
└────────┬────────┘
         ↓
┌─────────────────┐
│  3. 整合信息    │
└────────┬────────┘
         ↓
┌─────────────────┐
│  4. 生成回答    │
└─────────────────┘
```

**应用场景**：
- 企业知识库问答
- 客服机器人
- 文档分析
- 法律咨询

---

### Fine-tuning（微调）

**专业解释**：
微调是在预训练模型基础上，使用特定领域或任务的数据进行额外训练，使模型适应特定场景的过程。

**形象比喻**：
预训练模型像"大学毕业生"，有通识知识；微调像"职业培训"，让它成为某个领域的"专家"。

**微调 vs RAG**：

| 对比项 | 微调 | RAG |
|--------|------|-----|
| 知识更新 | 需重新训练 | 实时更新 |
| 成本 | 高 | 低 |
| 适用场景 | 固定领域、风格定制 | 动态知识、企业应用 |
| 技术门槛 | 高 | 中 |

---

## 四、新兴概念

### VibeCoding（氛围编程）

**专业解释**：
VibeCoding是由Andrej Karpathy于2025年提出的编程范式，核心是"人类定调、AI落地"，开发者用自然语言描述意图和氛围，由AI生成代码。

**形象比喻**：
传统编程像"写菜谱"，每一步都要精确；VibeCoding像"点菜"，你描述想要什么口味，AI帮你做出来。

**核心流程**：
```
描述氛围 → AI生成 → 运行测试 → 反馈调整 → 迭代优化
```

**适用场景**：
- 快速原型开发
- 个人项目
- 创意验证

**详见**：[AI核心概念 - VibeCoding](./03-ai-concepts.md)

---

### Embedding（嵌入/向量化）

**专业解释**：
Embedding是将文本、图像等数据转换为高维向量表示的技术，使计算机能够理解和计算语义相似度。

**形象比喻**：
Embedding就像给每个词/句子一个"坐标"。意思相近的词，坐标位置也相近。比如"猫"和"狗"的坐标比"猫"和"汽车"更接近。

**应用场景**：
- 语义搜索
- 推荐系统
- RAG知识检索
- 相似度计算

---

### Hallucination（幻觉）

**专业解释**：
幻觉是指模型生成看似合理但实际上是错误或虚构信息的现象。

**形象比喻**：
幻觉就像AI在"一本正经地胡说八道"。它自信地给出答案，但内容可能是编造的。

**如何减少幻觉**：
1. 使用RAG提供准确信息
2. 要求模型标注信息来源
3. 对关键信息进行验证
4. 使用更可靠的模型
