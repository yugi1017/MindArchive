# 第9章 AI智能体、MCP与Skills

> Agent智能体原理、MCP协议详解、Skills技能系统，理解AI的"大脑、能力、连接"三层架构

## 2026年的核心变化：Skills取代Prompt

### 为什么Skills成为核心？

> 2026年，AI行业已完成代际跃迁：**Agent Skills取代Prompt工程，成为智能体核心竞争力**。

**传统方式的局限**：
- Prompt工程需要不断调优
- 每次对话都要重新描述
- 难以复用和共享

**Skills的优势**：
- 一次定义，反复使用
- 可共享、可迭代
- 告别"Prompt内卷"

### Skills是什么？

> Skills是AI智能体的"技能包"，告诉AI在什么情况下该使用什么能力。

**定义一个"数字员工"，只需要从安装一个Skill开始。**

## AI智能体的三层架构

### 核心概念

2026年，AI智能体已经从实验室概念走向真实场景。其核心是由Agent、Skills、MCP组成的三层技术架构：

```
┌─────────────────────────────────────┐
│        Agent（大脑）                 │
│    决策、规划、协调                   │
│    "想做什么"                        │
├─────────────────────────────────────┤
│        Skills（能力）                │
│    专业技能、工作流程                 │
│    "怎么做"                          │
├─────────────────────────────────────┤
│        MCP（连接）                   │
│    连接外部工具、数据、服务           │
│    "能做到"                          │
└─────────────────────────────────────┘
```

### 三层的关系

| 层级 | 角色 | 职责 | 比喻 |
|------|------|------|------|
| Agent | 大脑 | 决策与规划 | 公司CEO |
| Skills | 能力 | 专业技能 | 专业团队 |
| MCP | 连接 | 对接资源 | 外部合作 |

## Agent：智能体的"大脑"

### 什么是Agent？

> Agent是能够自主感知环境、做出决策、执行行动的AI系统

### Agent的核心能力

| 能力 | 说明 | 例子 |
|------|------|------|
| 自主性 | 不需要人工持续干预 | 自动完成整项任务 |
| 环境交互 | 感知外部环境 | 读取文件、查询数据 |
| 目标导向 | 基于目标调整行为 | 根据反馈优化方案 |
| 学习适应 | 从经验中学习 | 记住用户偏好 |

### Agent vs 普通AI

| 维度 | 普通AI | Agent |
|------|--------|-------|
| 交互方式 | 一问一答 | 目标驱动 |
| 任务范围 | 单一任务 | 复杂任务链 |
| 工具使用 | 无 | 能调用工具 |
| 自主程度 | 被动 | 主动 |

## Skills：智能体的"能力"

### 什么是Skills？

> Skills是Agent的专业技能包，让它具备完成特定任务的能力

### Skills vs Prompt的本质区别

| 维度 | Prompt | Skills |
|------|--------|--------|
| **本质** | 纯文本指令 | 文件夹（指令+可执行代码+资源） |
| **能力边界** | 只能生成文本 | 能执行Python、操作文件、调用API |
| **工具调用** | 无 | 可调用MCP、执行脚本、操作浏览器 |
| **自由度** | 受限于模型能力 | 可扩展任意能力（写代码实现） |

### Skills能做Prompt做不到的事

| 能力 | 说明 | 实际案例 |
|------|------|----------|
| **执行Python代码** | 运行脚本处理数据 | 批量处理Excel、数据分析、生成图表 |
| **图片处理** | 调用PIL/OpenCV等库 | 压缩、裁剪、格式转换、添加水印 |
| **网页自动化** | 使用Playwright/Selenium | 自动填表、爬取数据、网页截图 |
| **文件批量操作** | 读写本地文件 | 批量重命名、格式转换、内容替换 |

**实际案例对比**：

```
任务：把100张图片压缩到100KB以下

❌ 用Prompt：
只能告诉你"可以使用PS或在线工具"，需要你手动操作

✅ 用Skills：
直接执行Python脚本，自动完成压缩，输出处理报告
```

### Skills的类型

| 类型 | 说明 | 例子 |
|------|------|------|
| 通用技能 | 基础能力 | 文本生成、翻译 |
| 专业技能 | 特定领域 | 法律咨询、医疗诊断 |
| 工作流技能 | 流程化任务 | 代码审查、报告生成 |

### 如何获取Skills

| 方式 | 说明 | 推荐渠道 |
|------|------|----------|
| 内置 | 工具自带的基础Skills | Claude Desktop、ChatGPT |

### Skills文件结构

```
my-skill/
├── SKILL.md           # 必需：技能说明文件（入口）
├── scripts/           # 可选：可执行脚本
├── templates/         # 可选：文档模板
└── resources/         # 可选：参考资料
```

### Progressive Disclosure：渐进式加载

> Skills最聪明的设计：**按需加载，不会爆掉上下文窗口**。

```
启动时 → 只读取每个Skill的name和description
识别时 → 根据请求判断需要哪个Skill
加载时 → 读取该Skill的完整SKILL.md
执行时 → 按需读取scripts/或resources/下的文件
```

**这意味着**：你可以有100个Skills，但每次对话只会加载相关的1-2个。

## MCP：智能体的"连接"

### 什么是MCP？

> MCP（Model Context Protocol）是连接AI与外部世界的"翻译器"，被誉为AI世界的"USB接口"

### 为什么需要MCP？

**问题**：
- AI只会"说AI语言"
- 各种软件有自己的"软件语言"
- 它们之间无法直接沟通

**解决**：
- MCP作为"翻译器"
- 让AI能连接各种工具和服务

### MCP的工作原理

```
┌─────────┐      ┌─────────┐      ┌─────────┐
│   AI    │ ←──→ │   MCP   │ ←──→ │ 外部工具 │
│  模型   │      │  服务器  │      │  服务   │
└─────────┘      └─────────┘      └─────────┘
     ↑                ↑                ↑
   AI语言          标准协议         工具语言
```

### 常用MCP服务器推荐

#### 文件操作类

| MCP服务器 | 功能 | 使用场景 |
|-----------|------|----------|
| filesystem | 文件系统读写 | 读写本地文件 |
| sqlite | SQLite数据库操作 | 本地数据库查询 |
| postgres | PostgreSQL数据库 | 企业数据库操作 |

#### 开发工具类

| MCP服务器 | 功能 | 使用场景 |
|-----------|------|----------|
| github | GitHub操作 | 仓库管理、PR处理 |
| git | Git操作 | 版本控制 |
| docker | Docker管理 | 容器操作 |

#### 搜索类

| MCP服务器 | 功能 | 使用场景 |
|-----------|------|----------|
| brave-search | Brave搜索 | 获取最新网络信息 |
| google-search | Google搜索 | 搜索引擎查询 |

## 三层协同工作示例

### Skills + MCP协同

> **Skills定义"怎么做"，MCP提供"能做到"**，两者结合才是完整方案。

#### 协同架构

```
用户请求
    ↓
Agent（大脑）：理解意图，规划任务
    ↓
Skills（能力）：按固定流程执行
    ↓
MCP（连接）：调用外部工具/服务
    ↓
执行结果
```

#### 协同案例：自动化PR代码审查

```
用户：审查GitHub PR #123

执行流程：
1. Skills识别：调用code-reviewer Skill
2. MCP调用：使用github MCP获取PR代码
3. Skills执行：按审查清单分析代码
4. MCP调用：使用github MCP发布审查评论
5. 输出：审查报告已发布
```

### 如何选择：Skills vs MCP vs Prompt

| 场景 | 选择 | 原因 |
|------|------|------|
| 固定流程任务 | Skills | 需要按步骤执行 |
| 访问外部服务 | MCP | 需要标准化接口 |
| 简单问答 | Prompt | 无需额外能力 |
| 复杂自动化 | Skills + MCP | 需要流程+工具 |

**判断流程**：

```
任务有固定流程吗？
├── 是 → 使用Skills
└── 否 → 需要访问外部数据吗？
         ├── 是 → 使用MCP
         └── 否 → 直接用Prompt即可
```

## Skills对智能体平台的冲击与重构

### 架构革命：从Workflow到Skills

> 2026年，AI Agent领域正经历一场架构变革：**Skills模式正在颠覆传统Workflow模式**。

#### 两种架构的本质差异

| 维度 | Workflow模式 | Skills模式 |
|------|--------------|-----------|
| **执行模式** | 预定义流程、顺序执行 | 按需调用、动态组合 |
| **决策权** | 开发者预设路径 | AI模型实时判断 |
| **内存占用** | 加载所有模块，占用高 | 按需加载，占用低 |
| **扩展性** | 添加功能需重构流程 | 只需添加新Skill文件 |
| **适用场景** | 固定流程、重复任务 | 复杂推理、复合型任务 |

### 开源Skills生态

> 截至2026年1月，全球已有**超过6万个公开可用的Skills**。

**主流Skills资源**：

| 资源 | 说明 |
|------|------|
| Anthropic官方Skills | 质量最高，最稳定 |
| Awesome Claude Skills | 社区精选合集 |
| Skills.sh | Skills搜索引擎 |

### 选择建议：Skills vs 智能体平台

```
你的需求是什么？
│
├── 快速上线、零代码需求
│   └── 选择智能体平台（扣子、Dify）
│
├── 复杂专业任务、需要执行代码
│   └── 选择Skills
│
├── 企业私有化、数据安全要求
│   └── 选择Dify/FastGPT私有部署
│
└── 跨平台兼容、持续迭代
    └── 选择Skills
```

### 什么是A2A？

> A2A（Agent-to-Agent）是智能体之间的通信协议，让多个Agent能协同工作

```
销售Agent → 订单数据 → 财务Agent → 发票处理 → 物流Agent → 发货
```

**客户服务**：

```
客服Agent → 问题分类 → 技术Agent → 问题解决 → 反馈Agent → 满意度调查
```
