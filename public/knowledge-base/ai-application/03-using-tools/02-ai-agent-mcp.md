# 第9章 AI智能体、MCP与Skills

> Agent智能体原理、MCP协议详解、Skills技能系统，理解AI的"大脑、连接、能力"三层架构

## AI智能体的三层架构

### 核心概念

2026年，AI智能体已经从实验室概念走向真实场景。其核心是由Agent、MCP、Skills组成的三层技术架构：

```
┌─────────────────────────────────────┐
│        Agent（大脑）                 │
│    决策、规划、协调                   │
│    "想做什么"                        │
├─────────────────────────────────────┤
│        MCP（连接）                   │
│    连接外部工具、数据、服务           │
│    "能做到"                          │
├─────────────────────────────────────┤
│        Skills（能力）                │
│    专业技能、工作流程                 │
│    "怎么做"                          │
└─────────────────────────────────────┘
```

### 三层的关系

| 层级 | 角色 | 职责 | 比喻 |
|------|------|------|------|
| Agent | 大脑 | 决策与规划 | 公司CEO |
| MCP | 连接 | 对接资源 | 外部合作渠道 |
| Skills | 能力 | 专业技能 | 专业团队 |

## Agent：智能体的"大脑"

### 什么是Agent？

> Agent是能够自主感知环境、做出决策、执行行动的AI系统

### Agent的核心能力

| 能力 | 说明 | 例子 |
|------|------|------|
| 自主性 | 不需要人工持续干预 | 自动完成整项任务 |
| 环境交互 | 感知外部环境 | 读取文件、查询数据 |
| 目标导向 | 基于目标调整行为 | 根据反馈优化方案 |
| 学习适应 | 从经验中学习 | 记住用户偏好 |

### Agent vs 普通AI

| 维度 | 普通AI | Agent |
|------|--------|-------|
| 交互方式 | 一问一答 | 目标驱动 |
| 任务范围 | 单一任务 | 复杂任务链 |
| 工具使用 | 无 | 能调用工具 |
| 自主程度 | 被动 | 主动 |

## MCP：智能体的"连接"

### 什么是MCP？

> MCP（Model Context Protocol）是连接AI与外部世界的"翻译器"，被誉为AI世界的"USB-C接口"

### 为什么需要MCP？

**问题**：
- AI只会"说AI语言"
- 各种软件有自己的"软件语言"
- 它们之间无法直接沟通

**解决**：
- MCP作为"翻译器"
- 让AI能连接各种工具和服务
- **一次配置，到处使用**

### MCP的工作原理

```
┌─────────┐      ┌─────────┐      ┌─────────┐
│   AI    │ ←──→ │   MCP   │ ←──→ │ 外部工具 │
│  模型   │      │  服务器  │      │  服务   │
└─────────┘      └─────────┘      └─────────┘
     ↑                ↑                ↑
   AI语言          标准协议         工具语言
```

### 2026年MCP生态爆发

> 截至2026年，国内已有**超过12万项MCP服务**，覆盖各行业各领域。

**核心趋势**：产品开始不仅面向人类，也面向AI开放MCP接口。

### 如何配置MCP？

#### Claude Desktop配置示例

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@anthropic-ai/mcp-server-filesystem", "/path/to/allowed/dir"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@anthropic-ai/mcp-server-github"],
      "env": {
        "GITHUB_TOKEN": "your-github-token"
      }
    }
  }
}
```

## Skills：智能体的"能力"

### 什么是Skills？

> Skills是Agent的专业技能包，让它具备完成特定任务的能力

### 2026年的核心变化：Skills取代Prompt

> **Skills取代Prompt工程，成为智能体核心竞争力**

**传统方式的局限**：
- Prompt工程需要不断调优
- 每次对话都要重新描述
- 难以复用和共享

**Skills的优势**：
- 一次定义，反复使用
- 可共享、可迭代
- 告别"Prompt内卷"

### Skills vs Prompt的本质区别

| 维度 | Prompt | Skills |
|------|--------|--------|
| **本质** | 纯文本指令 | 文件夹（指令+可执行代码+资源） |
| **能力边界** | 只能生成文本 | 能执行Python、操作文件、调用API |
| **工具调用** | 无 | 可调用MCP、执行脚本、操作浏览器 |
| **自由度** | 受限于模型能力 | 可扩展任意能力（写代码实现） |

### Skills能做Prompt做不到的事

| 能力 | 说明 | 实际案例 |
|------|------|----------|
| **执行Python代码** | 运行脚本处理数据 | 批量处理Excel、数据分析、生成图表 |
| **图片处理** | 调用PIL/OpenCV等库 | 压缩、裁剪、格式转换、添加水印 |
| **网页自动化** | 使用Playwright/Selenium | 自动填表、爬取数据、网页截图 |
| **文件批量操作** | 读写本地文件 | 批量重命名、格式转换、内容替换 |

**实际案例对比**：

```
任务：把100张图片压缩到100KB以下

❌ 用Prompt：
只能告诉你"可以使用PS或在线工具"，需要你手动操作

✅ 用Skills：
直接执行Python脚本，自动完成压缩，输出处理报告
```

```

├── SKILL.md           # 必需：技能说明文件（入口）
├── scripts/           # 可选：可执行脚本
├── templates/         # 可选：文档模板

```

### Progressive Disclosure：渐进式加载

> Skills最聪明的设计：**按需加载，不会爆掉上下文窗口**。

```
启动时 → 只读取每个Skill的name和description
识别时 → 根据请求判断需要哪个Skill
加载时 → 读取该Skill的完整SKILL.md
执行时 → 按需读取scripts/或resources/下的文件
```

## 三层协同工作示例

### MCP + Skills协同

> **MCP提供"能做到"的连接，Skills定义"怎么做"的流程**，两者结合才是完整方案。

#### 协同架构

```
用户请求
    ↓
Agent（大脑）：理解意图，规划任务
    ↓
MCP（连接）：获取数据、调用外部服务
    ↓
Skills（能力）：按固定流程处理
    ↓
执行结果
```

#### 协同案例：自动化PR代码审查

```
用户：审查GitHub PR #123

执行流程：
1. MCP调用：使用github MCP获取PR代码
2. Skills执行：调用code-reviewer Skill分析代码
3. MCP调用：使用github MCP发布审查评论
4. 输出：审查报告已发布
```

### 如何选择：MCP vs Skills vs Prompt

| 场景 | 选择 | 原因 |
|------|------|------|
| 访问外部服务/数据 | MCP | 需要标准化接口 |
| 固定流程任务 | Skills | 需要按步骤执行 |
| 简单问答 | Prompt | 无需额外能力 |
| 复杂自动化 | MCP + Skills | 需要连接+流程 |

**判断流程**：

```
需要访问外部数据吗？
├── 是 → 使用MCP
└── 否 → 任务有固定流程吗？
         ├── 是 → 使用Skills
         └── 否 → 直接用Prompt即可
```
